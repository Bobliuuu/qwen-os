# 16 Test and regression (test.patch)

Goal: lock behavior so optimizations cannot silently change the game, and find out why DEMO1 diverged.

Method: goldens in `tests/golden/`: `doomd_m1_states.txt` (`<gametic> <fnv64>` of the DMC100 lockstep hash after every game tic of DEMO1, 260 frames), `doomd_m1_frames.txt` (md5-12 of every frame that differs from the previous), `doomd_m2_*` (E1M1 scripted, 100 frames), `perf_baseline.txt` (`m1 4210308 4050 257`, `m2 2042709 1421 97`: mean instr per tic, disk requests per tic, tics). `tools/doomd_regress.sh [--update]`, `tools/doomd_regress_cmp.py`, `tools/doomd_trace_cmp.py`, `tools/doomd_hashes.py`, `tests/test_doomd_regress.py` (determinism: same ELF twice gives identical console, regs, RAM; lockstep: Python reference and, if on PYTHONPATH, upstream reference agree with the C twin to 2,500,000 instr, three checkpoints), `tests/test_model_doom_plan.py`, `tools/build_oracle_mac.sh` (host oracle built on macOS).

Bug found: the DEMO1 frame divergence at unique frame 202 (tic 206). Root cause (patch notes): `ports/doomdmc/qsolid.c` (`R_SolidColumn` column reuse) copied the repeat column from the previous destination column in the strip buffer, which had been overdrawn (row 199 x=190,191 = colour 1) before the next plane column, so the overdraw was replicated over the next 8 columns. Fix: keep the last computed column privately as at most 24 runs (48 B). Cost about +1.2 % instr/tic. Bisect: noskip/nofix/noqimg/nobake/-Oz/orig-engine had no effect; nosolid identical to original; game state hashes identical in every build.
Observation: state hashes are optimization independent but not identical to the host oracle tic for tic: the guest object store lists mobjs in tier order, not spawn order, from tic 71 of DEMO1 on, and the hash uses target ordinals; compare single tics field by field with `doomd_trace_cmp.py`.
Merge status (TRACES/merge/regress1.log): in the merge tree the frames and m2 states are identical to golden, but `m1-states` diverges from tic 57 (139 of 260 lines differ), so `doomd_regress` FAILS there. Mean cost in that run: m1 3.09 M/tic (26.7 % below the 4.21 M baseline), 3,618 req/tic. Cause not diagnosed in this record (possibly the object-ordering/hash change or a merged engine file).
Result: worked; the qsolid bug is fixed in test.patch; regress on the merged tree is open.
Patch: TRACES/patches/test.patch (md5 2b8ad04f...; apply inside `repo2` with `patch -p2`).
