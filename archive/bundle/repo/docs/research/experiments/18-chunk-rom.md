# 18 Chunk ROM (chunkrom.patch, chunkrom-model.patch)

Goal: no disk pauses inside a model run chunk. Pre-fill the data ROM with exactly the disk extents the chunk will read.

Method: the guest (`qplat.c` `crx_read`, `-DQ_CHUNKROM`) looks each disk read up in an extent table at `Q_CRX_BASE = 0x28C00` in the data ROM (window to 0x3F000 = 91,136 B, about 89 KB); a hit is a ROM copy with no mailbox request. The host dry-runs the chunk on the C twin with `REQLOG` (offset, len, ra, tic, frame-marker count), builds the window (`tools/chunkrom.py`: 'CRX1' header, 257-entry guide, (disk offset, ROM address) table, blob; extents word-aligned), and writes it into the snapshot's data ROM at each chunk boundary (`fill_drom`). Window switches happen only at frame markers (the one place a model segment can always end). Planning: `--tics C` fixed chunks or `--greedy` longest chunks fitting a budget. `model_doom_qwen.py` gets `--rom-plan`/ROM segments (`chunkrom-model.patch`); `rv32_fast CRXPLAN=` applies a plan on the C twin.
Numbers: skip15 config issues 165,061 disk requests per 350 tics (TRACES/lowres, agent report quotes 165,054); with chunk ROM 4 requests; instruction overhead +6.6 % (agent report). The recorded greedy plan (TRACES/chunkrom/rom_plan.json) has 5 chunks over markers [0,5), [5,18), [18,33), [33,111), [111,152) with 547/583/578/400/348 extents. Dry run on the reference stand-in (TRACES/chunkrom/dry_rom.json): 2 segments (1 rom, 1 marker), 12,082,980 instr, 16,957,065 planned chip tokens for 4 frames, `tok_per_instr` 1.4034. Without the ROM window: 2,176 planned segments, 2,776,332 instr, 3,863,207 tokens for a smaller target (dry_norom.log).
Result: worked on the host and in the dry run; NOT executed on the real model. `E1M6` bake dropped in this build; `CHUNKROM=1` in `lowres.sh`.
Caveat: the 89 KB window conflicts with the 88 flats the RAM squeeze put in the data ROM (120 KiB used of 128) unless flats are dropped for that build; how the merge resolves this is open (see STATUS.md).
Patches: TRACES/patches/chunkrom.patch (2833b1b3...), chunkrom-model.patch (96e04ee8...). Analysis script: TRACES/chunkrom/analyze.py.
