# 15 OS flow: interactive shell, key ring, live demo (os.patch)

Goal: make DOOM an application launched from a shell with typed keys, rather than a firmware image.

Changes (from the patch's README text, verified): `make live` builds `qwenos-live.elf` (kernel `-DQOS_LIVE`, shell `-DSHELL_LIVE`). Cold boot prints no banner; guest prints `$ ` and parks in `KEY_WAIT` 184 instructions after reset. Shell (2 KiB of 4 KiB slot): echo, backspace, `ls`, `cat`, `echo > file`, `run /bin/X`, `exit`. `run /bin/doomd` takes over; mode 3 starts straight in E1M1 and plays on mailbox keys only. Keyboard mailbox is now a 4-deep ring (`u32 seq` + `u8 q[4]`, read counter in core RAM so keys survive exec/takeover); `KEY_WAIT` parks until a key arrives. `tools/keysched.py` and `rv32_fast -K` give scripted key schedules (`shell_ready <key>`, `frame N <key>`, `<instr> <key>`). `tools/qwenos_live.sh` runs `rv32_fast -L` (raw tty keys -> mailbox, serves E1.img, 24-bit ANSI display from PLAYPAL; quit Ctrl-]). `tools/os_demo.sh` replays boot -> typed `run /bin/doomd` -> E1M1 -> simulated play.

Measured (instructions on rv32_fast, README text of the patch): cold boot to prompt 184; typing 15 keys 1,050 (70 each); Enter -> doomd_main 2,509; doomd init to level start 130.5 K; level load + first frame 3.60 M; total cold boot -> first E1M1 frame 3.73 M (3.92 M with the old boot script and mode 2 on the same perf tree); later frames about 2.7 M with keys. Savings: no bss clear loop at boot (22 K), no boot script/banner, RAM zeroing moved to the kernel (25 K+), table CRC for image header (-29 K), direct framebuffer writes (about -30 K per frame), leaf fast paths for PUTC/KEY_WAIT/DISK_READ.
Result: worked on the emulator. Tests: `tests/test_shell_live.py`, `tests/test_live.py` (pty-driven; interactive tests need a TTY; GUI-event style checks are blocked by macOS permissions per memory notes).
Merge friction: TRACES/merge/os-apply.log shows os.patch applied onto the merge tree with failed hunks in `qlcd.c` (1 of 3), `qplat.c` (1 of 1) and `tools/rv32_fast.c` (4 of 6); rejects had to be merged by hand.
