## Existing comparison from the same microbench (other agent's Modal runs, `/Users/jhome/qwenos-work/perf/*.log`)

Settings: `--skip 3420000 --unroll 16 --profile`; mismatches are identical across GPUs (first at token 971), so exactness is the same.
A100/H100/L40S used 6000 tokens, A10G/L4 used 20000. us/token:

| GPU | A graph-only | B host loop | C K=16 per graph |
|---|---|---|---|
| A10G | 318.9 | 372.0 | 318.6 |
| L4 | 192.9 | 238.8 | 193.3 |
| A100-40GB | 241.1 | 278.2 | 243.3 |
| L40S | 164.7 | 185.5 | 166.5 |
| H100 | 203.4 | 225.2 | 204.7 |

A100 kernel time over 2000 tokens: `_head_kernel` 50%, `_ffn_kernel` 32%, `_apply_kernel` 15%.

Reading: rate does not scale with memory bandwidth or GPU class (L40S beats H100 and A100; H100 is only 1.19x A100),
and K tokens per graph gives no gain over graph-only, so the floor is per-kernel latency of a small sequential
workload, not launch overhead. B200 would very likely follow the same trend (an expectation, not a measurement).
Host-loop overhead is about 10-25% over graph-only.
