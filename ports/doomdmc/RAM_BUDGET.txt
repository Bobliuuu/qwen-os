Frame regions (RV32 sizes, always textured): plan A (w16) 15200 B, plans B/C/D (w8) 9596 B (a smaller plan
would overlap the front-end compose buffers at frame offset 7168..8368, so there is no w < 8 plan).
The converter picks A, else B per map and skill. Arena (level state + object pages) = what is left:
 plan A arena 9764 B (v1: 3848 B, E1M8 only), plan B arena 15324 B (v1: 9408 B).
E1, 27 map/skill combos: v1 3xA 19xB 1xC 4xD (and its frames show flat-colour floors)
                          v2 22xA 5xB, textured floors and ceilings everywhere, flats = ROM or the 1 slot.
 (QFLAT_SLOTS=0 for mklayout.py: 24xA 3xB, the ~3 % of sector flat references that are not in ROM go flat-colour.)
Measured with tools/rv32_fast (E1M1, DEMO1, frames 400-440): v1 5.10 M instr/frame (flat-colour floors),
v2 5.56 M (textured, w16; the same textured frames from disk flats cost 6.32 M, so ROM flats save 12 %).
Same image, same frame: ROM flats vs disk flats are pixel-identical. w8 instead of w16 costs +10 %.
Record cache: 16 sets x 4 ways x 16 B measured best (4: 5.38 M, 8: 5.19 M, 16: 5.01 M, 32: 5.25 M instr/frame
in the A/k0 experiments); 32 sets plus anything bigger than 4384 B no longer fits E1M7 skill 3 in plan B.
